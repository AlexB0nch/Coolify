# Почему висел HTTPS у skillcheck.natabiz.ru (19.08.2026)

## Симптом

HTTP (порт 80) отдавал редирект мгновенно, HTTPS (порт 443) висел до таймаута —
и снаружи, и с самого сервера. Приложение изнутри контейнера отвечало 200.

## Причина

Скиллчек переехал на docker-compose. Compose-файл создал собственную сеть
`<uuid>_default`, и api-контейнер оказался сразу в трёх сетях:

| Сеть | IP api | Прокси в ней? |
|---|---|---|
| `coolify` | 10.0.1.8 | да |
| `<uuid>` (сеть Coolify для приложения) | 172.28.1.3 | да |
| `<uuid>_default` (создал compose) | 172.28.2.2 | **нет** |

В traefik-метках приложения не было `traefik.docker.network`, поэтому Traefik
выбирал IP контейнера наугад — и выбрал 172.28.2.2 из сети, куда прокси не
подключён. SYN-пакеты уходили в никуда, запрос висел до таймаута.

Почему это выглядело загадочно:

* порт 80 работал — редирект на HTTPS Traefik отдаёт сам, не обращаясь к
  приложению;
* TLS-хендшейк проходил — его тоже терминирует Traefik;
* висел только следующий шаг: проксирование в недостижимый бэкенд.

Перезапуск прокси (первая напрашивающаяся мера) не помог бы: после рестарта
Traefik выбрал бы тот же адрес.

## Как нашли

`scripts/06-diagnose-https.sh` показал: 443 слушается и локально отвечает
(503 на голый IP — норма), DNS всех доменов в порядке. Дальше вручную:

1. `curl --resolve домен:443:127.0.0.1` висит, а `curl https://127.0.0.1/`
   отвечает мгновенно → виснет конкретный маршрут, а не точка входа;
2. в метках api-контейнера нет `traefik.docker.network`, контейнер в трёх
   сетях, прокси — в двух из них;
3. `docker exec coolify-proxy wget http://<ip>:8000/health` по каждому из трёх
   IP: отвечают два, третий висит — тот самый, который выбрал Traefik.

## Лечение

Мгновенное (уже применено):

```bash
docker network connect <uuid>_default coolify-proxy
```

Постоянное — в compose-файле скиллчека у сервиса, который смотрит в интернет,
указать сеть явно и передеплоить:

```yaml
services:
  api:
    labels:
      - traefik.docker.network=coolify
```

После передеплоя временное подключение можно снять:
`docker network disconnect <uuid>_default coolify-proxy`.

## Мораль

* У compose-приложений за прокси всегда проверяй метку
  `traefik.docker.network` — без неё Traefik выбирает сеть наугад.
* «Висит» и «отказ» — разные болезни: connection refused дал бы быстрый 502,
  вечное зависание — это пакеты в недостижимую сеть.
* Симптом «HTTP работает, HTTPS висит» не означает «сломан TLS»: на 80 живёт
  только редирект, и он маскирует смерть бэкенда.
